# Security Policy

## Supported Versions

| Version | Status |
|---------|--------|
| `main`  | ✅ Supported |

## Reporting a Vulnerability

Report security vulnerabilities **privately** via GitHub's
[Security → Report a vulnerability](https://github.com/VectisDev/Vigil/security/advisories/new).
Do not open public issues for security bugs.

We aim to acknowledge reports within **48 hours** and publish a fix or mitigation
within **7 days** for critical issues.

## Authentication Model

### Operator panel (`web/ops/`, `web/replay/`)

The panel uses a **client-side access gate** checked against `web/access.json`.

- **Access keys**: 12 random keys of 24 alphanumeric characters (~143 bits of
  entropy each), generated by the setup wizard and delivered once as a PDF.
  Plaintext keys are **never** stored in version control.
- **Stored hashes**: `web/access.json` holds only key hashes, in one of two formats:
  - **v3** — SHA-256 (current published format). Plain SHA-256 is adequate here
    because the keys are long random strings, not human passwords.
  - **v1** — PBKDF2-SHA256, 600 000 iterations, salt `centinel-admin-salt-v1`
    (written by the local setup wizard).
- **Session**: 8 hours in `sessionStorage`, cleared when the tab closes.

The gate is a convenience, **not a security boundary**: the panel is static HTML
served by GitHub Pages, so its code and data are public. Actions that change
state are protected elsewhere:

- **Local API** (`/api/setup/*`): configuration changes require a valid operator
  key in the `X-Centinel-Key` header, verified server-side in constant time.
- **GitHub**: dispatching workflows or editing configuration requires a GitHub
  token with the corresponding permissions.

## Cryptographic Integrity

Each data snapshot is hashed with SHA-256 and chained (each hash includes the
previous hash). Merkle roots are anchored to Bitcoin through OpenTimestamps,
providing an external, tamper-evident proof of existence. Witness and operator
records are signed with Ed25519.

## Scope

- The panel, admin, and replay pages are **static HTML** served via GitHub Pages.
- No secrets, database credentials, or private keys are stored in this repository.
- `web/access.json` contains **only key hashes** — never the keys.
- Every change is checked by CodeQL, code quality analysis, Dependabot and
  secret scanning (with push protection).
